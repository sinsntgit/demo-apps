Getting started

AskData turns a question written in plain English into a SQL query, runs it on your database and shows the answer as a chart, a table and a short summary. You never need to write SQL, but you can always see it, check it and correct it.

The five-step flow

  1. Pick a data model — the database (or folder of Excel / CSV files) you want to ask about.
  2. Pick an AI model — the model that will write the SQL.
  3. Ask your question.
  4. Check the SQL and the result. Confirm it if it is right, fix it if it is not.
  5. Explore — change the chart, export, or ask a follow-up.

Signing in

Sign in with the email and password your administrator gave you. A password set by an administrator is temporary: you are asked to choose your own straight away. Passwords need at least 10 characters with an upper-case letter, a lower-case letter and a digit.

If your organisation requires two-factor authentication you will be taken through setting it up before you can continue. See Security & 2FA.

Asking questions

Type your question in the box at the bottom of the Ask page and press Enter (Shift+Enter for a new line).

Writing questions that work well

  • Say what you want measured and how to break it down. “Total revenue by product category for 2025” is better than “sales info”.
  • Name the time period. “last quarter”, “since January 2025”, “by month”.
  • Say how many rows you want if it matters: “top 10 customers by revenue”.
  • Use your business's own words if they have been taught to the model under Training (for example “AOV”, “active customer”).
  • One question at a time. Ask the second part as a follow-up.

Follow-up questions

Within one chat the model remembers your last three answered questions and their SQL, so you can say “and by region?” or “only for laptops”. Under each answer you also get suggested follow-ups — click one to ask it.

A chat belongs to one data model. Changing the data model starts a new chat.

When the model asks you something back

If your question is ambiguous or the data model does not contain what you asked for, the model replies with a short clarifying question instead of guessing. Answer it in the same chat.

Review SQL before running

Tick Review SQL before running (top of the Ask page) if you want to see and approve the SQL before anything is run on the database. The answer then stops at the SQL with a Run this SQL button. This is useful on large or expensive databases.

Checking and correcting the SQL

Every answer shows the SQL that produced it and a sentence explaining the approach. The grey line next to “SQL” tells you which AI model wrote it, how long writing and running took, and whether it was auto-corrected or edited by you.

Charts and the chart controls

Every result can be viewed three ways using the buttons at the top right of the result: Chart, Table and Summary. AskData picks a sensible starting view; everything can be changed, and your choice is remembered for that answer.

Measures and categories

This is the one idea that explains all the controls:

  • A measure is a quantity that makes sense to add up or average — revenue, quantity, number of orders, impressions.
  • A category (also called a dimension) is a label that says what a row is about — product name, region, language, month, status.

Numbers that merely identify something are categories, not measures. A product ID, an order number, a postcode or a year should never be totalled — “sum of product IDs” means nothing. AskData recognises these from the column name (names ending in id, key, code, no, number, year, month, week, quarter and similar, holding whole numbers) and keeps them out of the Y axis list and out of totals and averages.

If you want to know how many rows fall in each category, choose Count of rows as the Y axis.

Reading the example above: “Bar · X axis = Language · Y axis = Total_Impressions · Add measure = Total_Revenue” means: draw one group of bars per language; the first bar is that language's impressions, the second is its revenue.

Two measures of very different size

Impressions may be in the hundreds of millions while revenue is in the thousands. On one shared axis the revenue bars would be invisible. When two measures differ by more than about 20×, AskData draws one panel per measure, each with its own scale, so both can be read. It never uses a second Y axis on the same chart, because that makes unrelated lines look related.

When several rows share the same X value

If you pick an X axis that repeats (for example region in a result that has one row per region and month), the chart adds those rows together so there is one bar per region. A note under the chart tells you when this has happened. Use Split by to see the breakdown instead.

  • Charts draw the first 300 rows of a result; the table always has every row returned.
  • At most 8 coloured series. Extra values in Split by are grouped as “Other”.
  • Wide, pivoted results (more than four measure columns, such as one column per month) open as a table, which is how they read best. You can still switch to Chart and pick one column as the Y axis.

Hovering

Move the mouse over any bar, point or slice to see its exact value.

Predictive questions: forecasts, predictions, segments, drivers, anomalies

AskData can go beyond “what happened” and run a statistical model on your data: project a figure forward, predict an outcome, group similar customers, show what drives a result, or point out what is unusual.

Turning it on

Tick 🔮 Use predictive capability at the top of the Ask page before asking. It is off by default and remembered between visits.

  • Unticked: every question gets an ordinary answer, however it is worded.
  • Ticked: a predictive analysis runs when the question calls for one. Ordinary questions are still answered the ordinary way.

What you can ask

KindExample questionsWhat you get
Forecast“Forecast revenue for the next 6 months” · “Project weekly orders to year end”The figure projected forward with a likely range, and an accuracy check on recent history.
Prediction“Which customers are likely to churn?” · “Predict order value from customer and product attributes”A prediction for every row (including those with no outcome yet), how often it is right, and what influences it.
Key drivers“What drives order value?” · “Which factors explain late deliveries?”The inputs ranked by how much they matter, with the direction of the effect.
Segmentation“Segment our customers” · “Group products into 4 clusters by sales behaviour”Groups of similar items, a profile of each, and which group every item belongs to.
Anomalies“Any unusual days in revenue?” · “Show unusual orders”The periods or rows that stand out, and by how much.

What happens when you ask

  1. The AI model writes the SQL that gathers the data needed for the analysis (for a forecast, the history by month; for a prediction, one row per customer with the outcome and the attributes) and names the method and the columns to use. That is all it does — it never sees the data and writes no analysis code.
  2. AskData runs the SQL on your database, with the usual read-only guard, data filters and masking.
  3. The AskData server prepares the data (feature engineering), fits the model, checks how good it is, and produces the charts, tables and explanation. Nothing is sent anywhere.

Reading the output

Every predictive answer has five parts. Use the Show: tick boxes above it to hide or show each one; your choice is remembered for that answer and used in the PDF.

PartContents
ExplanationThe key figures as tiles, then what was found in plain words: the result, the method used and why, how accurate it is, which inputs were used and which were left out (and why).
ChartsHistory with forecast and likely range; importance of each input; segments on a map; actual against predicted; unusual points marked.
ResultsThe answer as a table: forecast values, a prediction per row, the segment of each row, the unusual rows. Sortable, and exportable as CSV from ⬇ Export.
StatisticsThe supporting figures: accuracy check, models compared, quality by outcome, confusion matrix, importance with its spread, segment profiles.
CodeThe Python that produced the result — see below.

Amber notes at the top are warnings worth reading: too little history, an incomplete latest period, a result that is “too good” (an input probably contains the answer), or gaps that were filled in.

Below the predictive output, Data used shows the rows the SQL returned (the first 1,000 on screen; the analysis used all of them).

The code that ran

The Code part shows the exact Python script that was executed on the server for this answer, from the rows returned by the SQL to the final figures: data preparation, feature engineering, the models tried, the accuracy check and the final fit. Press Copy to take it away; with the SQL above it, a data scientist can reproduce the result.

The script is one of AskData's own tested routines with your column names and settings filled in. It is not written by the AI model.

Changing the settings

  • Forecast: change Periods ahead and press Update.
  • Segmentation: choose the number of Segments (or Automatic) and press Update.
  • For anything else — different inputs, a different period, another grain — say so in a follow-up question, or use Edit SQL: the analysis re-runs on whatever the SQL returns.

How each method works

KindMethodHow to judge it
ForecastThree methods are tried — Holt-Winters exponential smoothing (trend and seasonality), exponential smoothing of the recent level, and a naive “repeat the last value / cycle”. The most recent periods are hidden, each method forecasts them, and the closest is used. Seasonality is used only with two full cycles of history (24 months for monthly data). Quantities that are never negative are not forecast below zero.Typical error on the hidden periods, and vs naive guess: below 1 means the model beats simply repeating the past. If the naive guess wins, the series has no pattern to exploit — treat the forecast as a rough guide.
Prediction of a categoryLogistic regression and a random forest are both trained; each is scored on rows it has not seen (5-fold cross-validation) and the better one is kept.Accuracy against the Baseline (always guessing the commonest outcome). Balanced accuracy and ROC AUC show whether it can tell outcomes apart; 50% / 0.5 is a coin toss.
Prediction of a numberRidge regression and a random forest, compared the same way.R² (share of variation explained) and typical error against the error of always guessing the average.
Key driversThe prediction model above, then each input is shuffled in turn on held-back rows: the more the result suffers, the more that input matters (permutation importance).Importance is association, not proof of cause. Direction is given where it is clear.
SegmentationK-means clustering on standardised inputs. With Automatic, 2 to 8 segments are tried and the most distinct split is kept.Separation (silhouette score): above 0.5 is strong, below 0.25 means the groups overlap.
Anomalies over timeEach period is compared with the median of its neighbours; it is flagged when more than 3.5 robust standard deviations away.Unusual does not mean wrong — check flagged items against what you know.
Anomalous rowsAn isolation forest scores how easily each row is separated from the rest; at most the top 5% are flagged.

Feature engineering applied automatically: numbers are filled in where missing (median) and put on a common scale; text and category columns become one indicator per value, with rare values grouped; dates become year, month and weekday; time series are placed on a regular grid with gaps filled by straight line. Identifiers, free text, masked columns and columns with a single value are left out, and the explanation lists them.

Getting good results

  • Give it history. A forecast needs at least 6 periods and is far better with two years or more. A prediction needs at least 30 rows with a known outcome; hundreds are better.
  • Leave out the unfinished period. “…up to last month” avoids a half-complete month dragging a forecast down.
  • For predictions, ask for inputs known beforehand. A column filled in only after the outcome (a cancellation reason, a closing date) makes the result look perfect and be useless; AskData warns when it sees this.
  • Be specific about the outcome and the item: “predict whether an order is returned, per order, from channel, region and order value”.
  • If the message says the data is unsuitable, the query's data is still shown — adjust the question or the SQL and try again.
  • Confirm good answers. Pressing ✓ Correct saves the SQL together with the chosen method, so similar questions get the same treatment.

Limits

  • A predictive question may read up to 50,000 rows (an administrator can change this). Models are fitted on at most 20,000 rows, sampled at random when there are more; result tables keep the first 2,000 rows.
  • These are sound general-purpose methods, not a substitute for a specialist model built for one decision. Use the accuracy figures to decide how far to trust a result.
  • Data filters and masked columns apply: you can only model the data you are allowed to see.
  • In a report, a predictive answer is re-fitted on fresh data each time the report is opened or sent.

Table

Click a column heading to sort; click again to reverse. Results longer than 50 rows are paged. Empty values show as null.

Summary

The Summary explains in words what the result shows. It looks at the shape of the result and writes the explanation that fits:

If the result is…The summary tells you
A figure over time (by day, month, year…)The total and the average per period, the highest and lowest periods, the change from the first period to the last, how the latest period compares with the one before (with a warning if it looks incomplete), and whether the second half of the period is running above or below the first.
A figure for each category (by product, region…)Who leads and with what share of the total, the next two, the lowest, how concentrated the total is in the top three, and how many are above average. With two or more figures it also says when the leaders differ.
A figure broken down two ways (channel and category)The leader on each side and the single biggest combination.
A pivot table (one column per month, for example)The grand total, the largest and smallest rows across all columns, the highest and lowest columns, the change from the first column to the last, and the biggest single cell.
A plain list with no figuresHow many rows, and how the values in each column are spread.
One rowThe figures themselves.

Rules it follows so the explanation is correct:

  • Only quantities are totalled. Averages, rates, percentages and prices (columns whose names contain words like avg, rate, pct, price, margin) are averaged, never added up.
  • IDs, codes and years are categories, never totalled or averaged.
  • If the row limit was reached, it says the figures are partial.
  • Rows with no value are left out and you are told.

The table under the summary lists every column with its kind (measure, averaged measure, category, date) and its range.

The summary is calculated by the AskData server from the rows. It is not written by the AI model — the model never sees your results. Opening an older chat recalculates its summary with the current rules.

Chats and history

Every question and its result is saved automatically. Your chats are listed down the left of the Ask page, grouped by Today, Yesterday, Earlier this week, and then by month.

  • Open a chat by clicking it. Charts reappear exactly as you left them.
  • Rename — hover over a chat and click ✎. A chat is first named after its opening question.
  • Delete — hover and click 🗑. This removes the chat and its saved results for good.
  • Find — type in the Find a chat box above the list.
  • New chat starts a fresh conversation with no memory of earlier questions.

The History page lists every individual question you have asked, grouped by month, with its status. Search it by words in the question or the SQL; click a row to open the chat it belongs to.

Your chats are private to you. Administrators and stewards can see questions and SQL in the dashboard's query log for monitoring.

If your administrator has switched off result storage, chats keep the question and SQL but not the rows; press Run again to fetch fresh results.

Reports

A report brings together results from any of your chats — charts, tables and summaries — with your own headings and commentary, and can be exported to PDF, shared and scheduled.

A report stores the questions, not the numbers. Every time it is opened, each result is run again on the database, so charts, tables, summaries and any live text always show the latest data.

Creating a report

Two ways:

Sharing

A report is private until its owner shares it. Press 👥 Share and choose Can view or Can view and edit for:

  • User groups — everyone in a group set up by your administrator (for example “Sales leadership”). People added to the group later get access automatically; people removed lose it.
  • Roles — all analysts or all data stewards.
  • Individual people — one or as many as you like.

Sharing a report never widens anyone's access to data:

  • The report is refreshed for the person opening it. A result from a data model they cannot use shows “You do not have access…” instead of data.
  • Their data filters apply. Two people can open the same report and correctly see different numbers. A “🔒 your data filters applied” badge shows when this happens.
  • Masked columns stay masked.
  • Someone with edit rights can add only their own answered questions and cannot change the query behind an existing result.
  • Only the owner (or an administrator) can share, schedule or delete a report.

Your account, password and two-factor authentication

Click your name at the bottom of the left menu to open My account.

Turning on two-factor authentication (2FA)

  1. Install an authenticator app on your phone: Microsoft Authenticator, Google Authenticator, Authy, 1Password or similar.
  2. In My account press Set up 2FA.
  3. Scan the QR code with the app (or type in the key shown under it).
  4. Enter the 6-digit code the app shows and press Turn on 2FA.
  5. Save the 8 recovery codes you are shown. Each one can be used once in place of a code if you lose your phone. They are shown only once.

From then on, signing in asks for your password and then a code from the app.

What the AI model sees — and what it never sees

The AI model's only job is to write SQL. AskData runs that SQL itself, directly against your database, and sends the rows straight to your browser.

Sent to the AI modelNever sent to the AI model
  • Your question
  • Table and column names, data types, keys and comments
  • Approved training notes, examples and document passages
  • Earlier questions and SQL in the same chat
  • Query results — no rows, no totals, no charts
  • Anything from a predictive analysis: the model is fitted on the AskData server; the AI model only names the method and columns
  • Summaries (they are computed on the AskData server)
  • Database passwords or connection details
  • Literal values from database error messages

One optional exception, off by default and set per data model by an administrator: the distinct values of specific named columns (for example the list of order statuses) can be included to help the model write correct filters. Data models with this turned on show a badge “sample values shared with model” on the Data models page.

If even table and column names must stay inside your network, your administrator can configure a self-hosted AI model.

Training the system

“Training” here means giving the model the knowledge it needs about your data. Nothing is retrained: each time a question is asked, AskData finds the most relevant pieces of what you have taught it and hands them to the model along with the schema. Changes take effect on the very next question.

Training is kept separately for each data model. Choose the data model at the top of the Training page.

Importing examples in bulk

On the Question → SQL tab press Import CSV / JSON.

  • CSV: a header row with the columns question and sql.
  • JSON: [{"question": "…", "sql": "…"}, …]

Each SQL is checked: anything that is not a single read-only SELECT is skipped and reported. An example whose question already exists is updated rather than duplicated.

How to improve accuracy

  1. Sync the schema.
  2. Write documentation for every metric people ask about and every non-obvious code or flag.
  3. Add examples for your ten most common questions.
  4. Watch the dashboard's query log for failed and corrected questions. Each one tells you what note or example is missing.
  5. Clear the review queue regularly.

Export (top right) downloads all approved training for a data model as JSON — keep it as a backup.

The AskData server must be able to reach the database over the network (firewall / allow-list).

Excel and CSV folders

  • Leave the folder blank and use the 📁 Files button to upload, or enter a folder path that exists on the AskData server.
  • Supported: .csv, .tsv, .txt, .xlsx, .xlsm, .xls, .parquet; up to 200 MB per upload.
  • Each CSV file becomes a table named after the file. An Excel file with one sheet becomes one table; with several sheets, one table per sheet named file_sheet. Names are lower-cased and spaces become underscores (Sales 2025.xlsx, sheet North → sales_2025_north).
  • The first row must be the column headings. Keep one table per sheet, starting in cell A1, with no merged title rows.
  • Files are re-read automatically when they change. Press Sync schema after adding or removing files or columns.
  • Files are loaded into memory on the server, so very large files need a server with enough RAM.

User groups

Admin → User groups. A group is a named list of users — a team, a department, a management layer. Groups are used in three places: a group can be given access to a data model (and its own data filters), a report can be shared with a group, and a scheduled report can be emailed to a group.

  1. Press ＋ New group, give it a name and an optional description.
  2. Tick its members (use Find a user for long lists) and press Save group.
  • A user can belong to any number of groups.
  • Changing a group's members takes effect immediately: new members can open reports shared with the group and receive its scheduled emails from the next run; removed members stop.
  • Deleting a group removes the report sharing, schedule entries, data-model access and data filters that pointed at it. The users themselves are not deleted. Afterwards check Data access: a former member who still has access another way is no longer limited by the deleted group's filters.
  • A group on its own grants nothing. Give it access to data models, and limit the rows its members see, on the Data access tab.

  • Verify connects to the mail server and signs in, without sending anything. The Status column shows “✓ verified” or the server's error.

Below the senders is a log of the latest 200 emails: when, to whom, the subject, which report it was for, which sender, and whether it was sent, failed (with the mail server's reason) or simulated. “Sent” means the mail server accepted it; SMTP cannot confirm it reached the inbox.

If emails do not arrive

  • Check the recipient's spam folder and the Email log.
  • Most providers need an app password when two-factor sign-in is on for the mailbox.
  • The From address should be the mailbox you sign in with, or an alias it may send as.

  • Mailbox providers limit how many messages you can send per day; for large audiences use a transactional mail service.

Data access and data filters

Giving access to a group: tick Only selected groups and users may use it, tick the group under User groups, and press Save access. Every member of the group can then use the data model. Groups are created on the User groups tab.

  • A person has access if they are ticked individually or belong to any ticked group. The list of individual users shows “already has access via …” next to people covered by a ticked group.

Data filters — limiting the rows people see

A data filter is a condition on one table. Whenever a person it applies to runs a query that touches that table, they only get the rows that meet the condition.

FieldMeaningExample

Applies toEveryone (except administrators), everyone with a role, everyone in a user group, or one person.Group: North sales team
Filter is activeUntick to suspend it without deleting.

Per-person rules without one filter per person: use a placeholder that is replaced by the signed-in person's own details.

PlaceholderReplaced byExample condition
{user_email}Their sign-in emailsales_rep_email = {user_email}
{user_name}Their nameaccount_manager = {user_name}

How filters are enforced

  • The server applies them, not the AI model. Before any query runs, every mention of a filtered table is swapped for “that table, limited to the allowed rows”. This happens for model-written SQL, SQL the user edits by hand, and reports.
  • The SQL shown to the user stays as written; a “🔒 Your data filters are applied” badge appears on the result.
  • If several filters on the same table apply to someone (say one for their role, one for a group they belong to and one for them personally), they must satisfy all of them. Someone in two groups that each have a filter on the same table sees only rows allowed by both.
  • A group filter follows membership: it applies to people while they are in the group.
  • Administrators are never filtered.
  • A filter removes rows from the table it names. Queries that join to that table inherit the limit through the join — orders joined to North-only customers give North-only orders. A query on orders alone is not limited by a filter on customers; if orders must be limited too, add a filter on orders (for example region_code = 'N').
  • A query the server cannot analyse with certainty is refused for filtered users rather than run unfiltered.
  • Conditions are checked when saved: they must be a single condition, with no sub-queries.

Every filter change is recorded in the audit log.

Installation and operations

Requirements

  • Python 3.11 or newer (developed and tested on 3.13), or Docker.
  • Network access from the server to your databases and to the AI model provider.
  • A modern browser. Nothing is installed on users' machines.

Install and run

From the text2sql folder. A virtual environment keeps AskData's packages separate from other Python software on the machine.

# Windows (PowerShell)
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt -r requirements-drivers.txt
python -m uvicorn app.main:app --port 8000

# macOS / Linux
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -r requirements-drivers.txt
python -m uvicorn app.main:app --port 8000

Open http://localhost:8000. To let other machines connect add --host 0.0.0.0.

requirements-drivers.txt holds the database drivers. You may remove the lines for databases you do not use.

First sign-in

On the very first start an administrator account is created. Unless you set the variables below, the email is admin@example.com and a random password is printed once in the server window.

VariablePurpose
T2S_SECRET_KEYSigns sign-in sessions and encrypts stored database passwords and API keys. Set this yourself in production and keep a copy. If it changes, stored passwords and keys can no longer be read and must be re-entered. If unset, one is generated and saved in the data folder.

PowerShell example: $env:T2S_SECRET_KEY="…"; python -m uvicorn app.main:app --port 8000

Docker

cp .env.example .env      # then edit .env and set T2S_SECRET_KEY
docker compose up --build

This starts AskData on port 8000 with a PostgreSQL database for its own records.

Going to production

  • HTTPS: put AskData behind a reverse proxy (nginx, IIS, a cloud load balancer) that terminates TLS, and set T2S_COOKIE_SECURE=1.
  • Metadata store: use PostgreSQL rather than SQLite.
  • One process per instance. Scale by running more instances against the same PostgreSQL store.
  • Turn on mandatory 2FA in Admin → Settings.
  • Read-only database accounts for every data model.

Backup and restore

Back up two things: the data folder (or the PostgreSQL metadata database, plus the files sub-folder of the data folder) and the secret key. To restore, put both back and start the server. To move servers, copy both across.

Upgrading

Back up first. Replace the application files, reinstall requirements, restart. New tables are created automatically.

Resetting everything

Stop the server and delete the data folder. The next start creates a fresh, empty installation. This erases all users, connections, training and history.

Frequently asked questions

Can AskData change or delete my data?
No. Only single SELECT statements are run, connections are opened read-only where the database supports it, and you should give it a read-only account as well.

Does the AI provider see my data?
It sees questions, table and column names and your training notes. It never sees query results. See What the AI model sees.

Why did the same question give different SQL today?
Models are not perfectly repeatable, and training may have changed. Confirming a good answer as Correct pins it as an example, which makes that question consistent.

Why is a number column not offered on the Y axis?
It looks like an identifier, code or period (see Charts). It is still available as the X axis, in Split by, and with Count of rows. If it really is a quantity, ask the question so the column gets a clearer name — “…as total_units”.

Can I ask across two data models at once?
No. A question runs against one data model. If two sets of data need combining, an administrator can expose them through one database connection.

How fresh is the data?
Live. Every question runs on the source at that moment. Reopening a saved chat shows the result as it was; use Edit SQL → Run to refresh.

Can I share a result?
Put it in a report and share that, or export it as PDF, Excel, CSV or PNG. Chats themselves are private to each user.

Does it work in other languages?
You can ask in any language the chosen AI model understands. Training notes in the same language as the questions work best.
